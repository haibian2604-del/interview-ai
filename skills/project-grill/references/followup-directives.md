# 追问指令（真实面试项目题触发追问时拼接进 followupText）

## 模板

`{{anchor}}` 代入本题 followup_anchor，`{{improvements}}` 代入评估的 improvements（ loader 负责替换，模板本身不得改写字段名）：

```text
本项目题正在问穿一条 Claim（考察点：{{anchor}}），评估发现回答的不足：{{improvements}}。追问规则：只追一个最关键的缺失证据，一次只问一个问题；优先追这些风险信号——模糊词（负责/优化/提升）没有对象动作和证据；报了数字说不清口径（baseline/周期/来源）；强表述（主导/架构/Owner）划不清个人边界；只会 happy path 说不清失败与回滚；背术语定义说不清在项目中的作用；与简历或前面的回答矛盾。候选人明显卡住时降阶为最小事实问题；不要替候选人补造项目事实。
```

## 示例

输入：`anchor = 分库分表改造`，`improvements = 说不清个人负责边界`。

追问指令实例开头应为：「本项目题正在问穿一条 Claim（考察点：分库分表改造），评估发现回答的不足：说不清个人负责边界。追问规则：只追一个最关键的缺失证据……」

面试官收到指令后应产出类似这样的追问（口语化、不逐字念规则）：「这里面分片键的选型是你自己定的吗？当时为什么用用户 ID 而不是订单号——迁移老数据的时候你负责的是哪一段？」

## 为什么这样设计

- **只追一个证据**：追问预算每题仅 1 次（状态机硬顶），面面俱到等于都没追透。
- **风险信号清单**：简历深挖的高频穿帮点就是模糊词、无口径数字、强表述、happy path、背术语、前后矛盾这六类。
- **降阶不恋战**：候选人卡住时降阶为最小事实问题仍答不出，就该交回状态机换题——继续加压只会得到编造的答案。
